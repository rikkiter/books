# REST API: проект MVP

Контракт: [openapi.json](openapi.json). Просмотр: [swagger.html](swagger.html). Это проект, сервер и интеграции ещё не реализованы. Swagger UI загружает JS/CSS из CDN; выполнение запросов отключено. Генерация: `python docs/build_openapi.py`.

## Область версии 0.1

Общий REST API для Flutter, React и операторской панели. JSON, UUID, время UTC в ISO 8601, целочисленные баллы. Базовый путь `/api/v1`. Одна книга в заказе, доставка пока без денежных тарифов. Подписки, возврат прокатной книги, платежи и автоматическая интеграция с курьером вне этой версии.

Book — конкретное издание, Copy — физический экземпляр. Отдельную сущность произведения можно добавить позднее. Клиент заказывает Book; подходящий Copy выбирает backend. Цена фиксируется в заказе, адрес сохраняется снимком.

## Допущения и вопросы

- Подтверждено пользователем: баллы начисляются после окончательной приёмки оператором. Это уточнение заменяет исходное правило idea.md о начислении после передачи курьеру. Передача, получение на складе и проверка — отдельные шаги.
- Подтверждено пользователем: полученная книга остаётся в собственности пользователя; прокатного возврата нет.
- По заявке отсутствующая книга приобретается вручную; уведомление ведёт к обычному заказу. Бронь за заявителем отсутствует. Возможность отказа добавлена как предлагаемое исключение: исходное описание обещает закупку без ограничений.
- Каталог публичный, остальные пользовательские действия требуют входа.
- Согласие с оценкой, отмена до отправки, одна книга в заказе, бесплатная доставка и операторские подтверждения — проектные допущения.
- Нужно уточнить географию, тариф доставки, постаматы, сроки резерва, неуспешную доставку, повреждения и возможность нескольких книг в заказе. API для них пока не обещан.

## Состояния

Приёмка: `submitted → evaluated → accepted → handover_scheduled → handed_over → received → credited`. Отмена возможна до handed_over; отказ оператора — submitted/evaluated/received. Оценка может изменяться до её принятия пользователем. Окончательная проверка атомарно создаёт экземпляр и единственное начисление согласованного числа баллов. При неприемлемом состоянии после получения баллы не начисляются; создаётся задача урегулирования возврата. Условия и стоимость такого возврата требуют уточнения.

Заказ: `confirmed → shipped → delivered`; `confirmed → cancelled`. Создание атомарно резервирует экземпляр и списывает баллы; отмена атомарно возвращает их и освобождает экземпляр. Доставка и отмена конкурируют за блокировку одного заказа.

Заявка на закупку: `submitted → purchasing → available`; возможен переход submitted → available для уже поступившей книги. Отказ submitted/purchasing → rejected — предлагаемое правило.

## Надёжность и доступ

- Для операций с заказами, начислениями и переходами обязательна Idempotency-Key. Область: пользователь + метод + путь; срок 24 часа. Повтор с тем же телом возвращает тот же результат; с другим — 409. Уникальные ограничения бизнес-операций действуют независимо от срока ключа.
- Ledger неизменяемый: начисление, списание, возврат — отдельные записи. Баланс не может стать отрицательным. Для операций кошелька и экземпляра нужны транзакции и согласованный порядок блокировок.
- Изменение бизнес-состояния и запись outbox выполняются вместе. Worker повторяет уведомления и внешние действия; потребитель идемпотентен. Redis не является источником истины.
- Пользователь видит только свои приёмки, адреса, заказы, заявки, upload и устройства. Чужой ID возвращает 404. Операторские роли проверяются backend, а не только Swagger UI. Роль нельзя назначить через профиль.
- Авторизация: Flutter получает OAuth access token Яндекса через LoginSDK, backend запрашивает `/info`, проверяет `client_id` по серверному allowlist и идентифицирует пользователя по `(yandex, id)`. JWT LoginSDK и authorization code endpoint `/auth/yandex` не принимает. Собственный access token до 15 минут, собственный refresh token с ротацией и серверным отзывом. Flutter хранит refresh в защищённом хранилище. React callback, cookie-схема и CSRF ещё не входят в контракт. Подробности и границы: [yandex-id.md](yandex-id.md).
- Фото: закрытые bucket, временные ссылки, проверка владельца и purpose, 10 MiB на файл, 1–6 файлов на приёмку, проверка фактического типа/размера, удаление EXIF. MinIO upload сам по себе не означает принятие книги.
- Пагинация курсорная, максимум 100 элементов. Списки операций сортируются по created_at DESC, id DESC; каталог и рекомендации используют стабильный порядок, зафиксированный курсором. Фильтры включаются в курсор.
- Ошибки имеют code, message, request_id; 422 использует ту же оболочку (в FastAPI нужен свой handler). Примеры бизнес-кодов: BOOK_UNAVAILABLE, INSUFFICIENT_POINTS, PRICE_CHANGED, INVALID_TRANSITION, IDEMPOTENCY_CONFLICT.

## Проверка контракта

Генератор проверяет ссылки на схемы, уникальность operationId и параметры путей. Это структурная проверка, не полный валидатор OpenAPI и не тест реализации. Перед генерацией клиентских SDK и CI следует подключить полный OpenAPI validator.

Формат: [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html). При реализации можно подключить контракт к Swagger UI FastAPI либо сопоставить с автоматически генерируемой схемой: [Extending OpenAPI](https://fastapi.tiangolo.com/how-to/extending-openapi/).
